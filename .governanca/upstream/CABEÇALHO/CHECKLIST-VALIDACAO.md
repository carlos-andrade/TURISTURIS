## Sintaxe e apresentação no GitHub

- [ ] Existem as duas linhas de controlo: SHA-256 canónico e commit de referência.
- [ ] SHA-256 canónico recalculado segundo a norma, após normalização UTF-8/LF e exclusão apenas das duas linhas de controlo.
- [ ] O hash canónico não é confundido com o Git blob SHA.
- [ ] Commit de referência aponta para um commit anterior real, quando disponível.

- [ ] O ficheiro Markdown começa com um título `#` claro.
- [ ] Os metadados estão numa tabela Markdown com cabeçalho `Campo | Valor`.
- [ ] A tabela usa linha separadora e renderiza corretamente no GitHub.
- [ ] YAML front matter não substitui o cabeçalho visível.
- [ ] As secções usam níveis de título coerentes (`##`, `###`).

## Identificação

- [ ] Projeto e repositório identificados.
- [ ] Tipo documental e fase definidos ou justificados como não aplicáveis.
- [ ] ID único, estável e não reutilizado.
- [ ] Título coerente com o conteúdo.

## Estado e controlo de versão

- [ ] Estado documental corresponde à situação real.
- [ ] Versão e datas usam o formato definido.
- [ ] Aprovador, data de aprovação e vigência preenchidos quando aplicável.
- [ ] O autor não autoaprovou documento de alto impacto sem autoridade adequada.

## Autoridade e rastreabilidade

- [ ] Origem identificada.
- [ ] Autoridade superior referenciada.
- [ ] Cadeia `PROMPTS → CARTAS → LAYOUT ÚNICO → CÓDIGO` preservada quando aplicável.

- [ ] Ligações declaradas verificadas.

## Conteúdo

- [ ] Escopo, objetivo e dependências registados.
